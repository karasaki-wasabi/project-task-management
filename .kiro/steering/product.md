# Product Overview

タスク・案件を一元管理する社内向けタスク/案件管理アプリケーション。個人の学習(仕様駆動開発・CI/CD・AWSの段階的実践)を目的として開発しているが、実装は実運用に耐える品質を目指す。利用者はメールアドレス・表示名・パスワードでアカウントを自己登録し、HttpOnly Cookie セッションでログインして利用する。

## Core Capabilities

- タスク管理
  - 作成・優先度・メモ、親子階層化とタスク分割
  - 開発段階（通常／完了／中止）への配置。タスク全体の完了は完了種別の段階への到達で判定し、そのとき完了日時（`completedAt`）を打刻する
  - ステータスは段階内の作業状態のみを表す（未着手／作業中／引継待ち／保留）。タスク全体の完了を表す値は持たない
  - クローズ（完了または中止の段階にある状態）を基準に、未クローズの子がある親を完了段階へ移すことを拒否する
- 案件管理
  - 案件の登録と、必須タスクの進捗算出（完了段階にある必須タスクを数え、中止段階の必須タスクは母数から除外する）
  - 必須タスクが未クローズのまま案件終了日を過ぎた場合を明示
- カレンダー表示
  - タスクの期限日(点)と案件の期間(バー)を月表示のカレンダー上で俯瞰できる、「いつまでに何をすべきか」の一覧機能
  - 期限超過の対象はクローズ済みでないタスクに限る
- 繰り返しタスク生成
  - 案件連動テンプレートのみ
  - 起点は案件開始日・案件終了日・案件期間内の各月初・各月末の4種で、非負の固定方向オフセットと非営業日ポリシー(そのまま登録/登録しない/次営業日/前営業日)を考慮してタスクを生成する
  - 案件への付与は常時自動同期ではなく、案件の新規作成時および編集保存時に利用者が確認した適用操作だけを実行する
  - テンプレートは停止・再開できる
- 非営業日マスタ
  - 手動登録と、外部祝日APIからの手動同期(自動ポーリングはしない)
  - 繰り返し設定画面とは分離する
- 消化数ダッシュボード
  - 期間別の完了タスク数集計（`completedAt` の期間フィルタ）と簡易フォーキャスト
- 担当者フィルタ
  - タスク一覧を担当ユーザーで絞り込み
- ワークスペース
  - 作成・所属・ヘッダーでの現在選択
  - 新規ワークスペースには完了・中止の開発段階をそれぞれちょうど 1 つ用意する
  - 案件・タスク・繰り返し・非営業日・開発ステージは現在ワークスペースに帰属し、メンバー以外からは見えない
  - タスク作成・カンバン再割当の担当者候補は現在ワークスペースのメンバーに限定する（一覧フィルタ／カレンダー表示のユーザー取得は全アカウント一覧を用いる）
- 運用ログ基盤
  - アクセスログ・業務イベントログ・サーバーエラーログ・フロントエンドエラーログを`requestId`で相関させて構造化出力(CloudWatch Logs転送までを対象、集約・可視化基盤の構築自体はOut of Boundary)

## Target Use Cases

- 自己登録した開発者自身または少人数チームによる、案件と付随タスクの進捗管理
- 「いつまでに何を終わらせる必要があるか」をタスク単位・案件単位の両方の粒度で追跡すること

## Value Proposition

- 完成物としての価値に加え、以下の学習プロセス自体が目的
  - 仕様駆動開発(Kiro式 requirements → design → tasks → implementation)の実践
  - GitHub Actions を用いた CI/CD パイプラインの構築
  - AWS 上への段階的なデプロイ(S3/CloudFront・App Runner等 → RDS → ECS Fargate + IaC)
- 認証はアカウント登録と Cookie セッションによるログインまでを提供する。ワークスペースによるデータ分離（メンバーシップとリソース可視境界）は実装済み。RBAC、招待、外部 IdP、機械用トークン、通知、外部システム連携(JIRA等)は後続仕様として切り出す
