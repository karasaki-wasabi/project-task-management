# Product Overview

タスク・納品を一元管理する社内向けタスク/納品管理アプリケーション。個人の学習(仕様駆動開発・CI/CD・AWSの段階的実践)を目的として開発しているが、実装は実運用に耐える品質を目指す。認証機能は持たず、名前のみの軽量な担当ユーザーレコードによる選択制(Out of Boundary: ログイン・セッション管理)。

## Core Capabilities

- **タスク管理**: 作成・状態変更(未着手/進行中/完了/保留)・優先度・メモ、親子階層化とタスク分割。子タスクが未完了のまま親を完了にはできない。
- **納品(デリバリー)管理**: 納品の登録と、必須タスクの進捗算出。必須タスク未完了のまま納品期日を過ぎた場合を明示。
- **カレンダー表示**: タスクの期限日(点)と案件の期間(バー)を月表示のカレンダー上で俯瞰できる、「いつまでに何をすべきか」の一覧機能。
- **繰り返しタスク生成**: 固定間隔/納品連動の2種のテンプレートから、非営業日ポリシー(そのまま登録/登録しない/次営業日/前営業日)を考慮してタスクインスタンスを自動生成。生成のトリガー方式(cron等)自体はOut of Boundaryで、生成ロジックは手動トリガーAPIからも同一に実行できる。
- **非営業日マスタ**: 手動登録と、外部祝日APIからの手動同期(自動ポーリングはしない)。
- **消化数ダッシュボード**: 期間別の完了タスク数集計と簡易フォーキャスト。
- **担当者フィルタ**: タスク一覧を担当ユーザーで絞り込み。
- **運用ログ基盤**: アクセスログ・業務イベントログ・サーバーエラーログ・フロントエンドエラーログを`requestId`で相関させて構造化出力(CloudWatch Logs転送までを対象、集約・可視化基盤の構築自体はOut of Boundary)。

## Target Use Cases

- 開発者自身または少人数チームによる、納品物と付随タスクの進捗管理
- 「いつまでに何を終わらせる必要があるか」をタスク単位・納品単位の両方の粒度で追跡すること

## Value Proposition

- 完成物としての価値に加え、以下の学習プロセス自体が目的
  - 仕様駆動開発(Kiro式 requirements → design → tasks → implementation)の実践
  - GitHub Actions を用いた CI/CD パイプラインの構築
  - AWS 上への段階的なデプロイ(S3/CloudFront・App Runner等 → RDS → ECS Fargate + IaC)
- 認証・通知・外部システム連携(JIRA等)を意図的に持たない、責務の狭いツールとして設計している(スコープを広げる場合は別スペックとして切り出す方針)
