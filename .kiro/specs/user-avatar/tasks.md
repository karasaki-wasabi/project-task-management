# Implementation Plan: user-avatar

- [ ] 1. 生成アルゴリズムの実装(Foundation)
- [x] 1.1 ハッシュ・PRNG・機械生成配色パレットの実装
  - `userId`文字列からFNV-1a相当の決定的ハッシュを算出する関数を実装する
  - ハッシュを種にmulberry32系の決定的PRNGを生成する関数を実装する
  - 色相を`N=12`分割(30度刻み)し、暖色/緑〜オリーブ/青緑〜青/紫〜ピンクの4色相帯ごとに固定のS/L代表値を割り当てる配色パレット生成関数を実装する。差し色・背景色は主色の色相から式で算出し、個別の手動チューニング値は持たない
  - 同一`userId`を渡すと常に同一のパレットインデックス・主色/差し色/背景色(CSS `hsl()`文字列)が得られることをその場で確認できる状態にする(観測可能な完了条件)
  - _Requirements: 1.1, 1.4_

- [x] 1.2 グリッド塗り分け・3種対称軸・塗りセル数ガードの実装
  - 5×5グリッドの各セルを 空白42%/主色36%/差し色22% の確率で独立抽選するロジックを実装する
  - 対称軸(左右反転/上下反転/点対称)を`userId`由来のPRNGから3択で決定的に選択し、点対称時は中心セル(2,2)を単独抽選、それ以外は軸に応じたペアで同一トーンを共有する処理を実装する
  - 独立領域(反転2種は15セル、点対称は13セル)の塗りセル数が独立領域サイズの34%〜74%に収まるまで、同一PRNG列の続きから最大12回reroll(引き直し)し、12回到達時は最後の結果を採用するガード処理を実装する
  - `generateUserAvatarPattern(userId: string)`として1.1のパレット生成と統合し、グリッド・配色・対称軸を含む単一のパターンオブジェクトを返す形に仕上げる
  - 同一`userId`を複数回渡した際に、グリッド・配色・対称軸を含む結果が完全に一致することをその場で確認できる状態にする(観測可能な完了条件)
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 1.3 生成アルゴリズムの単体テスト
  - 同一`userId`への複数回呼び出しが常に同一の結果を返すことを検証するテストを書く
  - `userId`以外の値(表示名相当の文字列等)を渡してもパターンに影響しないことを検証するテストを書く
  - 塗りセル数が範囲外になる`userId`を用意し、rerollにより範囲内に収束すること、および12回到達時に最後の結果がそのまま返ることを検証するテストを書く
  - 対称軸3種(左右反転/上下反転/点対称)がそれぞれ実際に選択されるケースを用意し、点対称時の中心セル単独抽選を検証するテストを書く
  - 大量(1000件規模)のダミー`userId`に対し、パレットインデックス・対称軸・グリッドの組み合わせが完全一致するケースが実用上ほぼ発生しないことを検証するテストを書く
  - テストスイート実行時にすべてのケースが成功することを確認する(観測可能な完了条件)
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

Requirement 5.1〜5.4(ユーザー設定ページ・画像アップロード機能・操作ログ文中埋め込み・ネイティブselect内表示を持たないこと)は、本仕様が意図的に実装しない境界事項であり、対応するタスクは存在しない。`WorkspaceSettingsModal`(名称・識別色の編集)もユーザー名を表示しないため差し込み対象外とする。design.mdの`Out of Boundary`と一致していることをもって充足を確認する。

## Implementation Notes

- 1.1: 配色の公開入口は `generateUserAvatarPalette(userId)`。4帯 S/L は暖色 70/50、緑〜オリーブ 55/42、青緑〜青 62/46、紫〜ピンク 58/50。差し色は h+32 / S-10 / L+14、背景は同色相 S=30 L=96。
- 1.2: `generateUserAvatarPattern` はパレット用とは別の同一シード mulberry32（Option A）。1回目パレット、2回目軸、以降トーン。塗り数ガードは独立領域の 34%〜74%、最大12 reroll。
- 1.3: テストシーム `generateUserAvatarPatternFromRng`。枯渇は 1〜11 回目と 12 回目で異なる範囲外塗り数を使い、12 回目採用を証明する。
