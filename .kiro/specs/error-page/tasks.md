# Implementation Plan

- [x] 1. statusCodeから表示内容を決定するロジックの実装と単体テスト
  - 404/403/401/500の4状態それぞれについて、design.mdの確定文言表どおりのアイコン種別・見出し・本文・ログイン導線要否を返す
  - 400番台(上記4値以外)は汎用4xx、500番台(500以外)は汎用5xxを返す
  - statusCodeが未定義、400未満、または600以上の場合は500と同一の内容を返す
  - 404/403/401/500/汎用4xx(例: 400, 409)/汎用5xx(例: 502, 503)/statusCode未定義または400未満または600以上のケースで、返却される内容(アイコン種別・コード・見出し・本文・ログイン導線要否)を検証する単体テストを書く
  - 上記ケース全ての単体テストがパスする状態が観測できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7_
  - _Boundary: useErrorPageContent_

- [x] 2. 画面表示とグローバルエラー捕捉の実装
- [x] 2.1 (P) 共通エラーページの表示と導線の実装
  - Nuxtのエラーバウンダリとして、statusCodeを表示内容決定ロジックに渡し、アイコン・コードバッジ・見出し・本文を描画する
  - 6状態(404/403/401/500/汎用4xx/汎用5xx)すべてで同一のレイアウト構造(アイコン+コードバッジ、見出し、本文、導線ボタンの配置)を保つ
  - 「ホームへ戻る」操作を常に表示し、押下するとアプリのトップページへ遷移する
  - 401のときだけ「ログイン画面へ」操作を追加表示し、押下すると現在のURLへの復帰情報を保持したままログイン画面へ遷移する
  - 画面遷移後もエラー状態が残り続けないよう、遷移操作はエラー状態を明示的に解除する形で実装する
  - 配色・ボタン・フォントは既存の`primary`/`slate`トークンとログイン画面のボタンパターンを再利用する。`tailwind.config.ts`にトークンは足さない。カード・アイコン円・コードバッジなど確定モック固有のユーティリティクラスは`error.vue`内で使ってよい
  - 401/403を発生させる新しい経路は追加しない。表示はstatusCodeを受け取ったときに行う
  - statusCode違いのモックを渡した統合テストで、対応する見出し・本文・ボタン構成(401のみ2ボタン)が描画されることを確認できる
  - 「ホームへ戻る」「ログイン画面へ」のクリックで、それぞれ正しい遷移先(トップページ、現在のURLへの復帰情報付きログイン画面)が呼び出されることをテストで確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2_
  - _Boundary: error.vue_

- [x] 2.2 (P) 実行時の予期しないエラーをエラーページ表示へ接続する
  - 既存のグローバルエラー捕捉(Vueのレンダリングエラー、windowのerrorイベント、unhandledrejectionイベント)の購読箇所は増やさず、既存の3箇所のみを使う
  - 既存の通報処理とは別に、エラーページ表示をトリガーする処理を独立した処理として追加する(通報処理自体の実装は変更しない)
  - windowのerror/unhandledrejectionイベントは、捕捉した値が実際のErrorインスタンスである場合にのみエラーページ表示をトリガーし、そうでない場合(無関係なノイズ)は従来通り通報のみ行う
  - Vueのレンダリングエラーはアプリ自身のコンポーネント内で発生したものに限定されるため、上記の絞り込みを行わず常にエラーページ表示をトリガーする
  - Errorインスタンスを渡した場合はエラーページ表示のトリガーと通報の両方が行われ、Errorインスタンスでない値を渡した場合は通報のみ行われることを、`frontend/plugins/error-reporter.client.test.ts`で確認できる
  - 既存の通報機能(レート制限を含む)が今回の変更後も従来通り動作することをテストで確認できる
  - テストのため`report`と`triggerErrorPage`をテスト可能な関数として切り出す(購読箇所は増やさない)
  - _Requirements: 4.2_
  - _Boundary: error-reporter.client.ts_
