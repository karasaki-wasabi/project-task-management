## プロンプト本文（ここからコピー）

```text
プロジェクト名の提案: workspace-membership（タスク管理 — ワークスペース作成・切替・メンバー管理）

目的
社内向けタスク/案件管理アプリ「Task Delivery Management」に、ログインユーザーが可視境界としての「ワークスペース」を作成し、既存の登録ユーザーを検索してメンバー追加できる機能を追加する。見た目は既存アプリのデザインシステムを踏襲し、専用の別ブランドにしない。Google Stitch は使わない。モックは実装前の確定用。

前提（既存アプリの状態）
- 直前の仕様（user-auth）でメールアドレス・パスワードによるログインが導入済み（設計確定・実装はこれから）。ログイン後のヘッダー右側には表示名と「ログアウト」が表示される想定
- 「ワークスペース」は案件（Case、納期付きの仕事単位）とは別概念。UI上でこの2語を混同させないこと（画面のどこにも「ワークスペース」と「案件」が並んだときに区別できるようにする）
- ワークスペース内のメンバーに役割・権限差はない（オーナー/一般のような表示を作らない）。ただし「削除できるのは作成者のみ」という業務ルールはある
- 招待リンクやメール送信はない。メンバー追加は既存登録ユーザーの検索のみ

参照する既存の視覚言語（厳守）
- ページ背景: slate-50 (#f8fafc)
- サーフェス: 白 (#ffffff)、枠は ring-1 ring-slate-200、角丸 rounded-lg (8px) / 入力・ボタンは rounded-md (6px)
- 影は使わない（フラット）。ただしモーダルのみ shadow-xl を伴う
- 本文・見出し: system-ui 系 sans-serif、h1 は text-xl font-semibold tracking-tight
- アクセント青 (#2563eb / hover #1d4ed8) は主要操作ボタンとリンク・フォーカスのみ。状態色としての青多用は禁止
- Primary ボタン: bg-blue-600 text-white text-sm
- Secondary ボタン: 白背景 + border border-slate-300
- 入力: border-slate-300、focus で青リング
- エラー: 画面上部の赤系アラートボックス（ErrorAlert 相当）。フィールド横の赤文字だらけにしない
- 一覧: 白背景 + ring-1 ring-slate-200 の table。ヘッダー行は text-xs uppercase tracking-wide text-slate-500、行区切りは border-slate-100
- モーダル: 中央寄せオーバーレイ（bg-slate-900/40）、パネルは rounded-lg bg-white ring-1 ring-slate-200 shadow-xl、右上に×閉じるボタン、下部に区切り線付きのアクション行
- side-stripe（左色線）禁止、ダークモードなし、display 書体なし、紫グラデやグラスモーフィズム禁止
- 既存ヘッダー: sticky、白背景、下線、左にアプリ名「Task Delivery Management」、その右にナビリンク（選択中は bg-blue-50 text-blue-700）、さらに右端に表示名＋ログアウト（user-auth 由来、今回はそのまま維持）

作ってほしい画面・要素（デスクトップ幅を主、モバイルも破綻しないこと）

1) ヘッダーへのワークスペース切替の追加（既存レイアウトの差分）
- 既存の sticky ヘッダー（アプリ名 → ナビ → 表示名/ログアウト）に、現在ワークスペースを示し切り替えられる要素を追加する
- 所属ワークスペースが複数ある場合はドロップダウン等で選べること。「ワークスペースを管理」のような、後述のメンバー管理画面への導線も置く
- 配置案を複数（例: ナビの左寄り、ナビと表示名の間、等）出し、比較の上で推奨を1つ明示してよい

2) ワークスペースが1つもない場合の空状態（初回登録直後など）
- 業務ナビの主要機能を隠す必要はないが、「ワークスペースがありません。作成してください」という趣旨を明確に伝える空状態カードを用意する
- 主要 CTA:「ワークスペースを作成」

3) ワークスペース作成（モーダル）
- 既存 Modal コンポーネントの型（中央オーバーレイ、右上×、タイトル/本文/アクションの3分割、アクション行は上に区切り線）を踏襲
- 入力: ワークスペース名（必須）
- 主要 CTA:「作成」、Secondary で「キャンセル」
- 名前未入力時のインラインまたは上部エラー表示

4) ワークスペースのメンバー管理画面（新規ページ、案件一覧などと並ぶ画面イメージ）
- 現在ワークスペースの名前を見出しに表示
- メンバー一覧（表示名・メールアドレスの一覧、ロール表示は無し）
- 「メンバーを追加」操作（ボタンから 5) の検索UIを開く）
- 作成者のみに見える「ワークスペースを削除」操作（Secondary、破壊的だが目立ちすぎない置き方。確認ダイアログ付き）
- 作成者以外がこの画面を見た場合は「削除」操作自体が出ない状態も1案として示してよい

5) ユーザー検索によるメンバー追加（4のページ内インライン、またはモーダルのどちらか一案）
- 表示名またはメールアドレスで検索する入力欄
- 検索結果をリスト表示し、各行に「追加」ボタン
- 既にメンバーであるユーザーは検索結果に出さない（「該当ユーザーがいません」等の0件表示も用意）
- 追加後は一覧に即座に反映される見た目

6) ワークスペース削除の確認
- 「本当に削除しますか」の確認ダイアログ（Modal パターン踏襲）。破壊的操作であることが分かる文言・配色（赤系は使うが警告色を画面全体に広げない）

情報設計の制約（要件準拠）
- ワークスペース内メンバーのロール・権限差を示すUIは作らない
- 招待リンク発行・メール送信のUIは作らない
- 案件（Case）一覧・詳細画面のUIは変更しない。「ワークスペース」の文言が「案件」と並んだときに紛れない見出し・ラベルにする
- メンバーの個別削除・自己脱退のUIは作らない（本仕様の対象外）

出力してほしいもの
- 上記 1〜6 の画面/要素モック（3〜5 は同一画面内の異なる状態として見せてよい）
- 各画面の主要コントロール一覧（ラベル文言つき）
- 採用推奨案を1つ明示（特にヘッダーのワークスペース切替の配置、5のインライン/モーダルどちらか）
- デスクトップを主とし、狭い幅での崩れ方の注意があれば短く記す

トーン
Operate モードの実用ツール。装飾より走査性。ヒーロー画像・統計・余計なマーケティング文は不要。
```
